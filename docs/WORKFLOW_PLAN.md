# 自动开发计划：模拟博彩平台（阶段 7）

> 这份计划由 `npm run autopilot`（`scripts/autopilot.mjs`）自动执行：
> **Codex 按顺序一步一步写代码 → 脚本自动提交 Git → Claude Code 自动审计 → 通过就进入下一步，不通过就带着审计意见打回给 Codex 重做。**
> 不允许跳步，也不允许一步里做下一步的事。详细需求见 [PLATFORM_TASK.md](PLATFORM_TASK.md)，规则见根目录 `AGENTS.md`（Codex）和 [workflow/AUDITOR.md](workflow/AUDITOR.md)（审计）。
> 进度看 [workflow/PROGRESS.md](workflow/PROGRESS.md)，每次审计报告在 `docs/audits/`。

**总原则**：演示平台，只用虚拟积分；不接任何真实支付、银行、加密货币；不收集真实收款信息。`src/engine/`（游戏规则）不改。

每一步的格式：`### STEP-xx 标题`，下面是"要做什么"和"验收标准"。脚本靠这个格式识别步骤，不要改格式。

### STEP-01 阶段 6 收尾

**要做什么**
- 运行 `npm run build`、`npm test`、`npm run check:provider`，修好所有错误（阶段 6 的代码之前没在本机跑过 build）。
- 不加新功能。

**验收标准**
- 三个命令全部通过。
- 如果改了代码，DEVLOG 写明改了什么、为什么。

### STEP-02 平台设计文档

**要做什么**
- 写 `docs/PLATFORM_DESIGN.md`：页面清单（玩家端、后台）、数据库表结构（字段、主键、唯一约束）、每种资金变动怎么记账（充值、提现申请/通过/拒绝、下注、派彩、回滚、后台手动调整）、对账公式、接口列表、目录结构。
- 只写文档，不写代码。

**验收标准**
- 覆盖 PLATFORM_TASK.md 里的全部页面和功能。
- 说清楚：余额为什么不会变负数、冻结金额怎么防止被拿去下注、同一交易号/同一提现申请为什么只会处理一次。
- 数据库用 `node:sqlite`，文件放在 `data/`。

### STEP-03 平台数据库和记账核心

**要做什么**
- 按设计文档实现数据库模块和记账核心（建表、玩家、钱包、资金流水），所有改余额的操作都在一个事务里完成。
- 写单元测试（用临时数据库文件）。
- 先不做网页、不接游戏。

**验收标准**
- 测试覆盖：余额不变负数、冻结金额不能用于下注、同一交易号只处理一次、同一提现申请不能通过两次、对账公式成立。
- `npm test` 通过（新测试要被 `npm test` 跑到）。

### STEP-04 平台服务接管钱包接口

**要做什么**
- 新的平台服务在 8788 端口运行，用 STEP-03 的记账核心实现 `/wallet/balance|bet|win|refund`（签名、交易号去重、回滚作废，行为和现在的 `mock-operator.mjs` 一致）以及调用游戏服务器 `/provider/launch`。
- `npm start` 启动新平台服务取代 `mock-operator.mjs`（旧文件可以删除或保留为参考，在 DEVLOG 说明）。
- `npm run check:provider` 改为针对新平台服务运行。

**验收标准**
- `npm run check:provider` 全部通过（包括派彩故障、扣款超时、余额不足）。
- `npm test` 通过。

### STEP-05 玩家注册、登录（接口）

**要做什么**
- 注册、登录、退出、获取当前玩家、修改密码的接口。
- 密码用 `node:crypto` scrypt 加盐哈希；登录状态用 httpOnly cookie；连续输错密码限制；被冻结的账号不能登录和下注。

**验收标准**
- 接口测试覆盖：重复用户名被拒、错误密码被拒、限流生效、未登录访问受保护接口返回 401、冻结账号被拒。
- 数据库里看不到明文密码。

### STEP-06 玩家网站：注册、登录、大厅、进入游戏

**要做什么**
- React 页面：注册、登录、大厅（游戏卡片 + 余额）、点卡片进入 Wild Frontier（通过 `/provider/launch`）。
- 每个页面顶部固定提示"演示平台 · 仅虚拟积分 · 不涉及真实货币"。手机上也能用。

**验收标准**
- `npm run build` 通过。
- 能完成：注册 → 登录 → 大厅 → 进入游戏 → 转一局 → 返回大厅余额已更新（在 DEVLOG 写清楚怎么验证的）。

### STEP-07 玩家钱包：充值、提现、资金记录

**要做什么**
- 充值申请（金额）、提现申请（金额，申请时冻结）、资金记录页（充值、提现、下注、派彩、回滚，带状态）。
- 不收集任何银行卡、账号等收款信息。

**验收标准**
- 提现金额超过可用余额（余额 − 冻结）被拒。
- 冻结中的金额在游戏里不能下注（钱包接口返回余额不足）。
- 测试覆盖以上两点。

### STEP-08 玩家：游戏记录、个人中心

**要做什么**
- 游戏记录页：我的每一局（时间、投注、赢分、局号），点局号打开回放。
- 个人中心：修改密码。

**验收标准**
- 玩家只能看到自己的记录（测试覆盖：拿别人的局号查不到）。
- `npm run build` 通过。

### STEP-09 后台：管理员、概览、玩家管理、操作日志

**要做什么**
- 管理员登录（与玩家账号分开；首次启动没有管理员时生成随机密码打印在终端）。
- 概览（玩家数、今日充值/提现、今日下注、今日派彩、平台盈亏）。
- 玩家列表/搜索/详情；冻结、解冻；手动调整余额（必须填原因，走资金流水）。
- 操作日志：管理员的每个操作。

**验收标准**
- 所有后台接口都检查管理员身份（测试覆盖：玩家 cookie 访问后台接口返回 401/403）。
- 手动调整余额会出现在资金流水和操作日志里。

### STEP-10 后台：审核、流水、游戏记录、对账、故障模拟

**要做什么**
- 充值审核、提现审核（拒绝时退回冻结金额）、交易流水（按玩家/类型/日期筛选）、游戏记录（点局号回放）、对账页（不一致标红）、故障模拟（派彩连续失败、扣款超时）。

**验收标准**
- 同一申请不能被审核两次（并发也不行，测试覆盖）。
- 对账页数字与资金流水一致。

### STEP-11 端到端检查和收尾

**要做什么**
- 新增端到端检查脚本（例如 `npm run check:platform`）：注册 → 充值申请 → 后台通过 → 玩 50 局 → 提现申请 → 后台通过 → 对账一致；另测余额不足不能提现、冻结金额不能下注、同一提现不能通过两次、同时 20 次下注不会扣成负数。
- `npm start` 打印玩家网站和后台网址；README 写清楚怎么启动、管理员密码在哪看。

**验收标准**
- `npm run build`、`npm test`、`npm run check:provider`、新的端到端检查全部通过。
- README 准确。

### STEP-13 顶部信息条、底部按钮条、MAX、自动旋转

**要做什么**（说明见 GAME_POLISH_SPEC.md 2.2）
- 顶部：主页图标｜金色描边面板（余额 / 投注 / 赢分）｜设置齿轮（菜单：游戏规则、返回大厅）。

**验收标准**
