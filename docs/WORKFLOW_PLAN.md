# 自动开发计划：模拟博彩平台（阶段 7）

> 这份计划由 `npm run autopilot`（`scripts/autopilot.mjs`）自动执行：
> **Codex 按顺序一步一步写代码 → 脚本自动提交 Git → Claude Code 自动审计 → 通过就进入下一步，不通过就带着审计意见打回给 Codex 重做。**
> 不允许跳步，也不允许一步里做下一步的事。详细需求见 [PLATFORM_TASK.md](PLATFORM_TASK.md)，规则见根目录 `AGENTS.md`（Codex）和 [workflow/AUDITOR.md](workflow/AUDITOR.md)（审计）。
> 进度看 [workflow/PROGRESS.md](workflow/PROGRESS.md)，每次审计报告在 `docs/audits/`。

**总原则**：演示平台，只用虚拟积分；不接任何真实支付、银行、加密货币；不收集真实收款信息。Wild Frontier 的规则（`src/engine/`）不改；阶段 9 的新游戏规则写在自己的目录。

每一步的格式：`### STEP-xx 标题`，下面是"要做什么"和"验收标准"。脚本靠这个格式识别步骤，不要改格式。

### STEP-21 中奖压暗变轻、手机上转动更流畅、自动旋转中奖多停一会

**背景**（用户录像 2026-10-12）：中奖瞬间非中奖格子被压得几乎全黑（`.reel-slot.is-dim img` 用了 `brightness(.28)`），符号变成灰黑影子，用户以为"停下后符号自己变了"；手机上转动不丝滑；自动旋转每局间隔只有约 0.3 秒，中奖一闪就过。

**要做什么**
- 非中奖格子只是"变淡"：形状和颜色仍能认出（例如 brightness 约 .6 ~ .7、轻微降饱和、不透明度不低于 .75）；中奖格子的加框、闪烁、百搭发光保持不变。
- 转动性能：转动中的符号图片不使用任何 CSS `filter`（对比度、饱和度、投影、亮度都去掉），停下后再恢复静止时的样式；转轴格子用 `transform: translate3d(...)` 并加 `will-change: transform`，避免每帧重绘。静止时的外观与现在一致。
- 自动旋转：本局有中奖时，下一局前至少等 2 秒（让中奖展示看清楚）；没中奖保持原来的短间隔。大奖动画、免费游戏的现有逻辑不变。

**验收标准**
- `npm run build`、`npm test` 通过；为自动旋转的中奖/未中奖间隔加测试（或把间隔做成导出常量并测试）。
- 转动中 `.reel-slot img` 的计算样式 `filter` 为 `none`；中奖时非中奖符号仍清晰可辨。DEVLOG 写明怎么检查的。

### STEP-22 转速调快一点

**要做什么**
