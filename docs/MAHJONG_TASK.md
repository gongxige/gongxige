# 第二款游戏需求：麻将连连胡（阶段 9）

> 用户整理的玩法参考了 PG 的《麻将胡了 2》。我们只借鉴**玩法和数学结构**（这些是通用的老虎机机制），做一款**自己的**游戏：
> - 名字用「麻将连连胡」（英文 Mahjong Cascade），**不用**"麻将胡了"、PG 的名字、标志。
> - **不用** PG 或任何参考游戏的图片、音效、动画、代码。麻将牌面、背景、按钮全部用 CSS / 内联 SVG / Canvas 自己画。
> - 和平台一样，只用虚拟积分。

## 一、用户给的规则

| 项目 | 规则 |
|---|---|
| 盘面 | 5 个卷轴；第 1、5 卷轴 4 行，第 2、3、4 卷轴 5 行（4×5×5×5×4 = 2000 种赢法，2000 ways） |
| 返还率 RTP | 96.95% |
| 最高赢分 | 1,708 倍总投注 |
| 波动性 | 中等 |
| 消除连锁 | 中奖的牌消除，上方的牌落下、空位从上方补牌，可以继续中奖，直到没有新的中奖 |
| 金色麻将 | 参与中奖的金色牌不消除，而是变成百搭（Wild） |
| 倍数 | 普通旋转：同一次旋转里第 1、2、3、4 次及以后的中奖分别 ×1、×2、×3、×5 |
| 免费旋转倍数 | 上限提高到 ×10，按 ×2、×4、×6、×10（用户只说了上限 10x，这个序列是按常见做法补的，设计文档里注明） |
| 免费旋转 | 盘面任意位置 3 个或以上"胡"字符号（Scatter）触发 10 次；每多 1 个"胡"再加 2 次；免费旋转中再出现 3 个以上"胡"，按同样规则追加次数 |

## 二、需要在设计里定下来的细节（STEP-23 写清楚，之后按设计做）

- **赢法**：从最左边卷轴开始连续 ≥3 个卷轴出现同一符号即中奖，路数 = 各卷轴该符号（含百搭）个数相乘。
- **符号**：建议高分 4 个（发、中、白、八万）、低分 4~5 个（筒、条类），加百搭、胡（Scatter）。赔付表由数学调校确定。
- **金色牌**：只出现在第 2、3、4 卷轴，是普通符号的金色版本（胡和百搭没有金色版）。
- **百搭**：只由金色牌变来（轴带上不直接放百搭），可替代除"胡"以外的所有符号；本身不单独成线。
- **胡（Scatter）**：本身不赔付（或设计文档另定）；在整次旋转（含所有消除连锁）结束时数盘面上的"胡"个数；"胡"不会被消除。
- **补牌要可重现**：空位从该卷轴轴带上方继续往上取牌，这样只凭初始停点就能 100% 重现整次旋转（回放、审计都靠它）。
- **最高赢分**：一次付费旋转加上它触发的全部免费旋转，总赢分封顶 1,708 倍；达到上限时免费旋转立即结束。
- **数学**：消除连锁很难精确计算，用大量模拟（至少 1,000 万次付费旋转，含免费旋转）确定 RTP，给出 95% 置信区间；"中等波动"用每局赢分的标准差和中奖频率说明标准，并给出实测值。
