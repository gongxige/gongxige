# 任务说明：做一个"模拟博彩平台"（用户端 + 管理后台），接入 Wild Frontier（阶段 7）

> 需求说明。开发按 [WORKFLOW_PLAN.md](WORKFLOW_PLAN.md) 的步骤由 `npm run autopilot` 自动进行（Codex 写、Claude Code 审计），下文"检查点"一节以 WORKFLOW_PLAN.md 的步骤为准。
> 本项目是 **Vite + React + TypeScript**，不是 Next.js：上层目录 AGENTS.md 里的 Next.js 规则不适用。
> 开工前先读 `CLAUDE.md`、`docs/DEVELOPMENT_PLAN.md`、`docs/PROVIDER_API.md`、`mock-operator.mjs`。
> `docs/CLOUD_DEPLOY_TASK.md`（上云）先不做。

## 一、要做成什么

用户在做调研学习，想亲眼看到一个平台从"注册 → 充值 → 玩游戏 → 提现"的完整流程，以及平台运营方在后台看到什么。

**这是演示，只用虚拟积分，只在本机运行：**

- 不接任何真实支付、银行、第三方支付、加密货币。
- "充值"= 填金额提交申请（或点"模拟支付成功"），后台审核通过后加积分。
- "提现"= 填金额提交申请，金额先冻结，后台审核通过才扣除；拒绝就退回。不收集银行卡号等任何真实收款信息。
- 每个页面顶部固定一条提示："演示平台 · 仅虚拟积分 · 不涉及真实货币"。

## 二、用户端（玩家用的网站）

| 页面 | 内容 |
|---|---|
| 注册 | 用户名 + 密码（两次确认）。用户名不能重复 |
| 登录 / 退出 | 登录后保持登录状态 |
| 大厅 | 游戏卡片（目前只有 Wild Frontier），显示余额；点卡片进入游戏 |
| 钱包 | 当前余额、冻结中金额；充值申请；提现申请；资金记录（充值、提现、下注、派彩、回滚，带状态） |
| 游戏记录 | 我的每一局：时间、投注、赢分、局号；点局号看回放 |
| 个人中心 | 修改密码 |

进入游戏：平台调用游戏服务器的 `/provider/launch`（按 `docs/PROVIDER_API.md`），拿到地址后打开游戏。游戏里的余额就是平台钱包的余额。

## 三、管理后台（平台运营方用）

| 页面 | 内容 |
|---|---|
| 管理员登录 | 独立于玩家账号。首次启动时如果没有管理员，就生成一个随机密码打印在终端里 |
| 概览 | 玩家总数、今日充值 / 提现、今日下注总额、今日派彩总额、平台盈亏（下注 − 派彩） |
| 玩家 | 列表、搜索；查看某个玩家的余额、流水、游戏记录；冻结 / 解冻账号；手动调整余额（必须填原因） |
| 充值审核 | 待审核列表，通过 / 拒绝 |
| 提现审核 | 待审核列表，通过 / 拒绝（拒绝时冻结金额退回） |
| 交易流水 | 所有资金变动，可按玩家、类型、日期筛选 |
| 游戏记录 | 所有局，点局号看回放 |
| 对账 | 每个玩家：余额是否等于"充值 − 提现 − 下注 + 派彩 + 回滚 ± 手动调整"，不一致标红 |
| 故障模拟 | 保留现在模拟平台里的"派彩连续失败""扣款超时" |
| 操作日志 | 管理员做过的每个操作（谁、什么时候、做了什么） |

## 四、技术要求

- **平台取代 `mock-operator.mjs`**：同样在 8788 端口；钱包接口 `/wallet/balance|bet|win|refund` 的行为（签名、交易号去重、回滚作废）必须和现在一样，`npm run check:provider` 必须继续通过。
- `npm start` 仍是一条命令启动全部（平台、游戏服务器、游戏网页），并打印平台网址和后台网址。
- **数据库**：用 Node 自带的 `node:sqlite`（不用装数据库），文件放在 `data/` 下（已被 Git 忽略）。
- **钱的正确性（最重要）**：
  - 余额只能通过"资金流水"改变，每笔流水和余额更新在**同一个数据库事务**里完成。
  - 余额任何时候都不能变成负数；提现申请时冻结的金额不能拿去下注。
  - 同一交易号只处理一次；同一个提现申请不能被通过两次。
- **账号安全**（即使是演示也按正确做法写）：密码用 `node:crypto` 的 scrypt 加盐哈希保存；登录状态用 httpOnly cookie；后台所有接口都要检查管理员身份；连续输错密码要限制。
- 前端用 React，界面简洁、手机上也能用；可以和游戏共用这个 Vite 项目（多页面入口），不要引入大型 UI 框架。新依赖要锁定确切版本号。
- `src/engine/` 不要改（游戏规则不变）。
