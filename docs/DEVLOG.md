## 2026-10-10 · 阶段 5：百搭 + 8 次免费游戏

**用户需求**：夕阳山景符号是百搭；金币出现 3 个触发 8 次免费游戏；13 个符号全部加入。

**做了什么**

- 素材：`extract_symbols.py` 新增矩形截取模式，从原视频第 640 帧截出百搭画卡（亮度参照同帧字母格的米色底）。现在共 13 个符号。
- 引擎：`WILD`、`WILD_REELS = [1,2,3]`、`FREE_SPINS_TRIGGER = 3`、`FREE_SPINS_AWARD = 8`；`evaluate` 中百搭在第 2–4 列计入任意 ways 符号；结果带 `freeSpinsAwarded`；新增 `playRound()`（一次付费旋转 + 它带出的全部免费游戏，供模拟用）。
- 卷轴：第 2–4 列各加 1 个百搭（试过 2 个，RTP 208%）；赔率表整体约 ×0.6。
- RTP：单局 85.29% + 免费游戏 11.53% = **96.83%**；触发率 1/67，每次触发平均 9.08 局（含再触发）。200 万轮模拟 96.80%、1/67、9.11 局。
- 服务端：会话增加 `freeSpins: { bet, remaining, played, totalWin }`；免费游戏期间忽略请求中的投注、不扣分；返回 `mode`、`freeSpinsAwarded`、`freeSpins`、`freeSpinsFinished`。新增 `STATE_FILE` 环境变量，测试服务器改用 `data/check-state.json`。
- 前端：触发弹窗"恭喜获得 / 再获得 8 次免费游戏"、顶部横幅、自动连转（未中奖 0.7s、中奖 1.6s 后下一局）、结束弹窗总赢分、免费期间背景换色、投注锁定、按钮显示"免费"；规则页加入百搭与免费游戏说明。

**怎么验证的**

- `npm test` 27/27（新增：百搭替代与路数、第 1 列百搭不替代、百搭不算金币、3 金币触发、免费游戏 RTP 关系、含免费游戏的种子模拟）；`npm run build` 通过。
- 接口实测：第 20 次触发，免费游戏中再触发（共 16 局），请求里故意传投注 500 仍按 50 结算，余额 = 触发后余额 + 免费总赢分。
- 浏览器实测：第 19 次触发弹窗（赢 400 = 3 金币 × 4 × 100），8 局自动转完，横幅逐局更新，结束弹窗"共 8 局 · 总赢分 364"后恢复正常；免费游戏转到第 2 局时刷新页面，从"剩余 6 局"继续并沿用投注 50。

**遗留 / 注意**

- 之前几次测试与用户共用存档，用户会话的虚拟积分被测试消耗（现为 6,722），另外留下了 `fs-test-*`、`port-check`、`diag` 几个测试会话记录。已改为测试专用存档。
- 用户需要重启 `npm run api` 才能用上免费游戏。

## 2026-10-10 · 重新截取符号素材

**为什么**：用户反馈"图标怪怪的"。放大检查发现三个问题：①上次加的柔边遮罩在每格留下一圈雾状光斑；②原素材是按固定格子位置截的，带着邻格碎片（如 9 上方的紫色弧线）和分隔线；③圆章类被切掉一边，且整体偏暗。

**做了什么**

- 新增 `scripts/extract_symbols.py`：从原视频（1280×720，`transpose=2` 转正）中，为每个符号挑一个干净的静止实例，把米色底从边缘漫水抠成透明，只保留中心图案（另留紧贴的小装饰，如皇冠、百合花），圆章再按椭圆轮廓裁掉上下邻格的圆弧，最后按米色底亮度把颜色提亮。
- 所有符号输出到同一尺寸透明画布（1 格宽 × 1.5 格高），金币、水牛这类大图案会像原游戏一样略微溢出格子。
- 9 在原视频静止画面中没有出现，改用第 199 帧（转动中但清晰）的完整 9。
- CSS：去掉柔边遮罩；图案按原比例居中；下方格子盖住上方格子；滚轮区域独立图层（`isolation: isolate`），不会压住大奖画面和提示框。
- 规则弹窗、大奖金币同步使用新图。

**怎么验证的**

- 生成对照图逐个检查 12 个符号（经过 4 轮调整：分隔线、邻格圆弧、金币两侧被削平、水牛细线）。
- 浏览器 1280×720 截图与放大检查：无光斑、无碎片，颜色正常；转动、停轮、中奖框正常；`npm run build` 通过。

**遗留 / 注意**

- 原视频分辨率决定了每格最多约 200×114 像素，所以图案不会比现在更清晰。
- 金币顶部、大象底部仍有极少量杂点；水牛本身是方形卡片造型（原图如此）。
- 重新生成需要原视频抽帧，见脚本开头说明（视频和抽帧都在本机，不进 Git）。

## 2026-10-09 · 阶段 2：滚轮转动动画

**做了什么**

- `src/game/reelMotion.ts`：单列运动。加速 260ms → 匀速（0.022 符号/ms）→ ease-out 减速并多冲 0.28 格 → 170ms 回弹到位。减速开始时速度与匀速一致，不会顿一下。
- `src/game/reelTape.ts`：滚动经过的就是真实卷轴条带；落点在画面外上方换成服务器停点，画面上已有的符号不会突变。
- `src/game/spinController.ts`：五列同时起转；结果到达后从左到右逐列减速（最早 500ms，间隔 400ms）；急停；请求失败也能安全停下。用 `tick(now)` 驱动，测试里可以模拟时间。
- `src/useReels.ts` + `src/ReelBoard.tsx`：`requestAnimationFrame` 每帧直接写 DOM，转动时 React 不重渲染；预加载全部符号图片。
- `App.tsx` 重写：点击立即转、结果并行请求、按钮在转动中变为"停止"、空格键、赢分从 0 滚动计数、中奖框改为盖在滚轮上的独立图层。
- 服务端返回 `stops`（各列停点）。
- 去掉旧的"中奖图案淡出成空框"效果（那是模仿视频，会把中奖符号藏起来），阶段 4 重新设计中奖表现。

**怎么验证的**

- `npm test`：23/23 通过；`npm run build` 通过。
- 浏览器 1280×720 实测：点击后 36ms 起转；五列在 1.07 / 1.48 / 1.80 / 2.23 / 2.65s 依次停下，2.83s 全部停稳。
- 逐帧读取 DOM：格子位置每帧向下增加约 30%，方向向下。
- 正常停止和急停后，画面上 5×4 符号都与服务器返回的 `grid` 完全一致。
- 急停：总时长 1.4s（正常 2.8s）。
- 中奖例子：9 四连 2×1×2×1 = 4 路 → 400，6 个格子高亮。

**遗留 / 注意**

- 部分符号图片边缘带邻近图案的残边（素材问题，阶段 3 处理）。
- 界面仍叠在参考截图上（阶段 3）。

## 2026-10-09 · 阶段 0 + 阶段 1：项目整理、数学引擎

**做了什么**

**怎么验证的**

- `npm test`：13/13 通过。

- 测试管理接口：非法值返回 400，合法值保存成功。

- 前端动画还是旧实现（阶段 2 处理）。
