## 2026-10-10 · 修复：大奖数字滚动被整段跳过

**现象**：用户想看特效，播放 `?preview-bigwin=60` 时，打开约 1 秒就已经是最终数字 4,800 并提示"点击继续"，随后自动关闭。

**原因**：上一版为了让后台标签页不卡住，在 `document.hidden` 时直接跳到最终值。浏览器面板在播放开始时对页面报告为"hidden"（1 秒只有 2 帧，约 26 秒后才变为 visible），于是整段滚动被跳过。

**修复**：`BigWin` 不再跳过，隐藏时改用 100ms 计时器按真实经过时间继续滚动，可见时用动画帧；切回来时看到的是当时应有的进度。

**怎么验证的**：面板可见时播放 60×：0.5s 535 → 2s 997 → 4s 1,916（BIG WIN、金币喷泉），继续升级到 MEGA / SUPER；`npm run build` 通过。

## 2026-10-10 · 修复：API 旧版本导致画面错乱、赢分显示 NaN

**现象**（用户截图）：中间赢分显示 NaN；蓝框框住的格子（狮子、金币）与实际中奖符号对不上；画面出现百搭但不参与结算。

**原因**：用户的 `npm run api` 进程是 10-09 21:38 启动的，早于百搭/免费游戏。Node 只在启动时加载一次引擎，所以服务器还在用**没有百搭的旧卷轴**算结果。网页用新卷轴（含百搭）按服务器给的停点停轮 → 画面上的符号与服务器结算用的盘面不同 → 高亮错位。旧接口不返回 `bet` → 赢分滚动计算出 NaN。

**修复**

- 新增 `src/engine/version.ts`：`ENGINE_VERSION` = 卷轴条带 + 赔率表 + 百搭列 + 免费游戏规则的指纹（FNV-1a）。
- 服务端在 `/api/config` 和每次旋转结果中返回 `engineVersion`；启动日志也打印。
- 网页加载时和每次旋转结果到达时核对版本；不一致时显示醒目提示（请重启 npm run api 并刷新），禁止旋转，并且不会把滚轮停在不一致的结果上。

**怎么验证的**

- 用户当前（旧）API：页面显示提示，旋转按钮禁用。
- 新 API（测试端口）：无提示；连转 12 次，每次画面 20 格与服务器 `grid` 完全一致，无 NaN。
- `npm test` 27/27，`npm run build` 通过。

**注意**：检查时向用户的旧 API 发了 1 次旋转请求，用的是单独会话 `version-probe`，不影响用户余额。
