# 游戏打磨说明：照参考游戏做好 Wild Frontier（阶段 8）

> 目标：把现在这款游戏做到"拿给合作伙伴看不掉价"的程度，手机上尤其要像成熟的 H5 老虎机。
> 参考对象：用户提供的同题材游戏（h5.hhh431.com，game=821）。它和我们的规则、赔付表完全一样，所以**只改画面和手感，不改规则**。
> 步骤见 [WORKFLOW_PLAN.md](WORKFLOW_PLAN.md) 的 STEP-12 ~ STEP-17。

## 0. 硬性边界

- `src/engine/`（规则、赔付、RTP）一律不改；结果仍由服务器决定，画面只负责展示。
- 不使用参考网站的任何图片、字体、标志或代码；只参考布局、节奏和风格。按钮、背景、边框用 CSS/内联 SVG 画，或使用项目已有的 `public/reels/` 素材。
- "演示平台 · 仅虚拟积分 · 不涉及真实货币"的提示必须一直可见，但不能盖住游戏（放进顶部信息条）。
- 电脑浏览器上的体验不能变差；平台、后台、钱包接口不动。

## 2. 现状 vs 参考 vs 要改成什么

### 2.1 手机布局（STEP-12）

- **参考**：铺满整个屏幕，没有黑边。手机竖着拿时，页面自己把游戏转 90°，横着显示，用户把手机横过来看即可。转轴几乎占满高度；上面一条信息条，下面一条按钮条。
- **我们现在**：竖屏时是屏幕中间一条很小的 16:9 横条，约 2/3 是黑的，并提示"横屏体验更好"；固定的"演示平台"横幅和"返回大厅"按钮压在画面上；横屏时左右有大黑边，顶部信息条被横幅挡住。
- **要改成**：
  - 手机（触屏、窄边 ≤ 600px）竖屏：整个游戏舞台旋转 90° 横向显示，宽 = 屏幕高，高 = 屏幕宽，铺满（`100dvh`/`100dvw`，考虑 `env(safe-area-inset-*)`）。触摸、点击坐标要跟着旋转后的画面正确响应（用 CSS transform 旋转整个舞台时浏览器会自动处理）。
  - 手机横屏：同样铺满，不留大黑边（允许舞台比例在 16:9 ~ 2.2:1 之间伸缩，转轴区域居中，左右空间给背景）。
  - 去掉压在游戏上的固定横幅："演示 · 仅虚拟积分"改为顶部信息条里的一行小字；"返回大厅"改为顶部左侧的主页图标按钮。
  - 去掉"横屏体验更好"提示（手机竖屏已自动横向显示）。
  - 电脑上保持现在的居中 16:9 舞台。

### 2.2 顶部信息条和底部按钮条（STEP-13）

参考布局（横屏，从左到右）：

- **顶部**：主页图标（圆角方块，紫色亮面）｜中间一块金色描边的深紫色面板，三栏：余额 CREDIT（金色数字，前面金币小图标）、投注 BET（红色数字）、赢分 WIN（金色数字）｜右侧设置齿轮。
- **底部**：`i`（规则）｜蓝色 `−`｜投注额白色输入框样式｜蓝色 `+`｜中间提示栏（深紫底、中间放射状光纹，显示"祝你好运 / 赢分 xxx"等）｜黄色 `MAX`｜蓝色 `自动`｜绿色大按钮 `SPIN`，下方一行小字"长按自动旋转"。
- 按钮风格：亮面"糖果"立体感——上半部高光、下半部深色、细白描边、按下时下沉 1~2px。全部用 CSS 渐变/阴影画，不用图片。
- 旋转中 SPIN 变成红色 `STOP`（快速停止）；大奖动画中按 STOP 跳过动画（现有逻辑基础上改样式即可）。
- **新功能**：
  - `MAX`：把投注直接设成允许的最高档（`ALLOWED_BETS` 最大值），旋转中不可用。
  - `自动`：弹出一个小面板选择次数（10 / 25 / 50 / 100），开始后按钮显示剩余次数，再点一次停止。自动旋转遇到以下情况立即停止：余额不足、触发免费游戏时（免费游戏照常自动进行，结束后不继续自动）、请求出错、玩家点击停止。
  - 长按 SPIN ≥ 0.6 秒：直接开始自动旋转（默认 50 次），与参考一致。
  - 设置齿轮：打开小菜单，至少包含"游戏规则""返回大厅"。
- **余额不足提示**：参考是居中的深紫色提示框（标题"提示"、内容"当前金币不足！"、绿色"确定"按钮）。我们改成同样样式的提示框，文案"余额不足，请回大厅充值"，按钮"确定"和"返回大厅"。

### 2.3 背景和转轴边框（STEP-14）

- **参考**：深蓝紫色的草原夜景（远处有树的剪影、近处的草/树枝），转轴外框是暖金色木框，四角有绳结装饰，左右两侧各有竖着的"1024 WAYS"牌子，框顶部中间有一个小三角标记。
- **我们现在**：纯色深蓝背景；金色渐变框，两根竖柱写"1024 WAYS"。
- **要改成**：用 CSS 渐变 + 内联 SVG 画出夜景背景（深蓝 → 紫的天空、几棵金合欢树剪影、底部草丛剪影，可加极淡的星点）；外框改为木纹质感（渐变 + 细描边）、四角绳结（SVG）、两侧"1024 WAYS"牌子保留但更像挂牌；转轴格子背景保持米白色。

### 2.4 转动手感（STEP-15）

参考一局（`ref-09-spin-10fps.png`，逐帧量出）：

- 按下后约 **0.5 秒**第一列停；之后每列间隔约 **0.4 ~ 0.5 秒**依次停，整局约 **2.5 秒**。
- 转动时**符号基本不糊**，速度明显比我们慢，每个图案在转动中都能看清；停下时有轻微回弹。
- **我们现在**：时间节奏接近（`FIRST_STOP_MS = 500`、`STOP_INTERVAL_MS = 400`），但速度快（`SPIN_SPEED = 0.022` 符号/毫秒）且加了较重的模糊（`.reel-column.is-spinning .reel-slot img { filter: blur(...) }`），看起来又快又糊。
- **要改成**：速度降到约 0.012 ~ 0.014 符号/毫秒（每秒约 12~14 格），去掉模糊或减到肉眼几乎看不出（≤ 0.05cqw）；保留回弹；保留两个金币后的"等第三个"效果（等待时间相应按新速度校准，仍然约 1 秒全速 + 1.5 秒减速）；快速停止保留。

### 2.5 中奖展示（STEP-16）

- **参考普通中奖**：中奖的格子外面套一圈浅色框，没中奖的格子变淡；赢分在底部提示栏里以金色大字显示并快速往上数。
- **参考大奖**：画面中央出现绿色放射光底 + 金色立体"BIG WIN"大字，下方黑色长条框里数字往上数（节奏慢，约每 0.15 秒 +1 的观感，总时长 3 ~ 6 秒），满屏金币雨；期间 SPIN 位置变成红色 STOP，点一下跳过。
- **我们现在**：已有 BIG / MEGA / SUPER WIN 三档（`src/ui/BigWin.tsx`，10× / 25× / 50× 投注）和金币雨；普通中奖逐条轮播。
- **要改成**：普通中奖时非中奖格子明显变淡、中奖格子加亮框；赢分显示在底部提示栏并往上数；大奖动画改成参考风格（绿色放射光 + 金色立体字 + 黑色数字条），三档阈值和现有逻辑保持不变。

### 2.6 符号图标（STEP-17）

- **参考**：动物是大而清晰的圆形徽章，几乎填满格子；字母（A K Q J 10 9）粗大立体。
- **我们现在**：`public/reels/*.png` 只有约 200×170 像素，放大后发虚；大小不统一，水牛是方形截图、边缘不干净。
- **要改成**：
  - 统一每个符号在格子里的显示尺寸和位置（填满约 90%），居中，不变形。
  - 用 CSS 给图标加清晰化处理（合适的 `object-fit`、轻微描边/投影），水牛做圆形或圆角裁切让它和其他动物一致。
  - **高清素材需要用户提供**。如果 `public/reels/` 里出现更高清的同名文件，代码不用改就能直接用上；这一步不要求生成新图片。

## 4. 验收方式说明

- 每一步都要 `npm run build`、`npm test` 通过；动到钱包或局记录时加跑 `npm run check:provider`。
- 画面类改动审计员无法亲眼看，所以每一步都要在 DEVLOG 写清楚改了哪些文件、在哪些尺寸下检查过（至少：电脑 1366×768、手机竖屏 390×844、手机横屏 844×390）。
- 能写成测试的要写测试（例如：自动旋转的停止条件、MAX 投注、转动时间常数）。
- 每一步通过审计后，Claude Code 会话会在浏览器里实际截图核对，并把结果告诉用户。
